# Сценарии поведения

- **Обновлено:** 2026-09-24
- **Статус:** сценарии исполняемые ([ADR 0003](../decisions/0003-executable-scenarios.md)).
  Зелёные — `auth.feature` (вертикальные срезы 1 и 2),
  `transcript.feature`, из `recordings.feature` — BR-13 и BR-14
  (вертикальные срезы 2 и 3), `processing.feature` целиком (срезы 3 и 3а), из
  `upload.feature` — BR-01, BR-03, BR-20, BR-21 (вертикальный срез 3);
  остальные пропускаются, пока у их шагов нет реализации.

## Как запускать

```bash
pnpm test:spec   # сценарии без @e2e: шаги steps/common + steps/domain
pnpm test:e2e    # сценарии @e2e: шаги steps/common + steps/e2e, браузер
```

Отчёт — `playwright-report/`. Сценарий, у которого нет хотя бы одного
шага, в отчёте пропущен (`skipped`), а не красный; какие шаги недостают,
перечисляет `pnpm test:missing`.

Слой между требованиями и кодом. Требование (`BR-XX` из
[requirements.md](../requirements.md)) говорит, что продукт должен делать;
сценарий здесь говорит, как выглядит выполненное требование, в терминах
чёрного ящика: что сделал пользователь и что он увидел.

## Зачем это

Спецификация, которую нельзя запустить, расходится с кодом молча. Поэтому
сценарии пишутся в Given-When-Then и в первом же вертикальном срезе
становятся исполняемыми тестами через `playwright-bdd`. Сценарий — это и
есть тест: отдельного теста, который пересказывает его кодом, нет.

**Правило:** требование без сценария не считается реализованным; сценарий
без тега `@BR-XX` не нужен.

## Формат

Gherkin, русские ключевые слова (`# language: ru`). Один файл на связную
область: `auth`, `upload`, `processing`, `transcript`, `recordings`,
`folders`.

- Каждый сценарий помечен тегом требования: `@BR-20`, `@NFR-04`.
- Сценарий без других тегов — доменный: шаги вызывают сервисы из
  `src/server/` напрямую, без браузера (`test:spec`, секунды).
- Тег `@e2e` — только если без запущенного приложения не проверить: что
  видно на экране или что ломается в HTTP-слое (`test:e2e`, минуты).
  Пограничные случаи — в пользу домена.
- Сценарий описывает поведение, а не устройство: «вижу сообщение, что
  принимаются только записи «Диктофона»», а не «в DOM появился
  `.error-toast`».
- Шаги переиспользуются между файлами: формулировка важнее краткости.

## Покрытие

```bash
comm -23 <(grep -o 'BR-[0-9]\+' docs/requirements.md | sort -u) <(grep -ho '@BR-[0-9]\+' docs/features/*.feature | tr -d '@' | sort -u)
```

Пусто, кроме `BR-32`, `BR-33`, `BR-34` (после MVP) — покрытие полное.

## Что сценариями не проверяется

- **NFR-01** (удобство на телефоне) и **NFR-05** (три экрана, ориентиры
  Voice Memos и MacWhisper) — это дизайн-ревью по макетам из
  [docs/design](../design/), а не тест.
- **NFR-03** (аудио на диске сервера) — архитектурное ограничение;
  проверяется код-ревью, а не поведением.
- **BR-06** в части качества распознавания — сценарий проверяет только, что
  система не портит ответ провайдера. Само качество на русском с
  английскими терминами проверяется на реальных записях при выборе
  провайдера ([ADR 0001](../decisions/0001-external-stt-provider.md)).

## Правила

- Правка требования → в той же правке пересмотреть все сценарии с его
  тегом: обновить, удалить или оставить осознанно.
- Шаг `Тогда` проверяет наблюдаемый результат: данные в базе, файл на
  диске, текст на экране. Шаг, который ничего не проверяет, делает
  сценарий зелёным и лживым.

## Решения, принятые в сценариях

Мелочи, которых нет в требованиях, но без которых сценарий не написать.
Если какое-то не нравится — правится здесь, это дешевле, чем в коде.

- Ошибка входа одинакова для неверного пароля и несуществующего логина.
- Очистка названия записи возвращает автоназвание, а не пустую строку.
- Время реплики показывается как `чч:мм:сс` («00:00:09») для записей
  любой длины, как в макетах: колонка времени одной ширины.
- Даты считаются в часовом поясе приложения (`Europe/Moscow`), а не
  сервера и не браузера.
- Группы списка: «Сегодня», «Вчера», «На этой неделе» (календарная
  неделя с понедельника), дальше по месяцам — «Сентябрь 2026».
- Автоназвание: дата загрузки без года, длительность (до минуты, не меньше
  1 мин; от часа — «1 ч 04 мин»), число спикеров, если запись готова и
  они есть: «19 сен, 42 мин, 3 спикера». Неизвестные части опускаются.
- Чужая запись неотличима от несуществующей: «Запись не найдена».
- Загрузка в чужую папку отклоняется (проверка из
  [architecture.md](../architecture.md), в требованиях явно не записана).
- Имена папок уникальны в пределах пользователя (из модели данных).
- Формат загрузки проверяется только по расширению `.m4a`; содержимое не
  проверяется — не тот файл вернётся ошибкой обработки с «Повторить».
- Ровно 3 часа ещё принимаются (BR-21); длительность — из заголовка
  файла, и она известна сразу после загрузки: запись в обработке уже
  называется «19 сен, 1 ч 04 мин».
- Причина сбоя обработки пользователю не показывается: «Не удалось
  распознать запись» и «Повторить».
