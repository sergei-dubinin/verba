# Бизнес-требования verba

- **Обновлено:** 2026-09-20
- **Статус:** черновик на ревью

## Цель

Получать из записанного аудио текст разговора, разбитый по спикерам, с
минимумом действий: загрузил файл, дождался, прочитал.

## Пользователь и сценарий

Пользователь записал разговор (встречу, созвон, интервью) диктофоном или
другим приложением и хочет получить его текст: кто что сказал, дословно.
Файл загружается с телефона или с компьютера.

Основной сценарий:

1. Пользователь открывает verba в браузере, загружает аудиофайл и, если
   хочет, выбирает для него папку.
2. Видит запись в списке со статусом «обрабатывается».
3. Когда обработка закончилась, открывает запись и читает транскрипт.
4. При желании переименовывает запись.

## Функциональные требования

### Загрузка

- **BR-01.** Пользователь может загрузить аудиофайл с телефона и с компьютера
  через браузер.
- **BR-02.** Загрузка — главное действие в интерфейсе, до неё одно нажатие с
  любого экрана списка.
- **BR-03.** При загрузке ничего не нужно настраивать: язык, число спикеров и
  другие параметры не указываются.
- **BR-20.** Поддерживается только формат приложения «Диктофон» на iPhone
  (`.m4a`). Файлы других форматов отклоняются при загрузке с понятным
  сообщением.
- **BR-21.** Ограничений на размер файла и длительность записи нет.

### Обработка

- **BR-04.** После загрузки запись обрабатывается автоматически, без
  дополнительных действий пользователя.
- **BR-05.** Спикеры определяются автоматически, их число заранее неизвестно.
- **BR-06.** Язык определяется автоматически. Речь на одном языке с
  вкраплениями терминов на другом (русский с английскими названиями) должна
  распознаваться без транслитерации терминов.
- **BR-07.** Пользователь видит статус каждой записи: обрабатывается, готово,
  ошибка.
- **BR-08.** Если обработка не удалась, пользователь видит, что произошла
  ошибка, и может запустить обработку повторно.

### Транскрипт

- **BR-09.** Результат — текст, разбитый на реплики. У каждой реплики указан
  спикер.
- **BR-10.** Подряд идущие реплики одного спикера группируются под одним
  именем спикера, как несколько сообщений подряд в Telegram: имя указано один
  раз, каждая реплика — отдельный абзац.
- **BR-11.** Спикеры по умолчанию называются «Спикер 1», «Спикер 2» и так
  далее, в порядке первого появления в записи. Переименовывать спикеров
  нельзя.
- **BR-18.** У каждой реплики показывается время её начала от старта записи.
- **BR-12.** Транскрипт доступен только для просмотра в интерфейсе.

### Записи

- **BR-13.** Пользователь видит список всех своих записей, новые сверху,
  сгруппированные по датам.
- **BR-14.** Запись получает название автоматически: дата, длительность, число
  спикеров («19 сен, 42 мин, 3 спикера»).
- **BR-15.** Пользователь может переименовать запись.
- **BR-16.** Исходное аудио хранится бессрочно, пока запись не удалена.
- **BR-19.** Пользователь может удалить свою запись целиком: транскрипт и
  аудиофайл. Удаление требует подтверждения и необратимо.

### Папки

- **BR-24.** Записи можно группировать по папкам. Папка — просто группа
  записей: клиент, проект, пресейл, что угодно. Вложенных папок и статусов
  у папок нет.
- **BR-25.** Папки личные: каждый пользователь видит и использует только свои.
  Общих папок нет.
- **BR-26.** При загрузке можно выбрать папку, но это не обязательно. Запись
  без папки показывается в разделе «Без папки».
- **BR-27.** Новую папку можно создать прямо при загрузке, не уходя с экрана.
- **BR-28.** Запись можно перенести в другую папку или убрать из папки после
  загрузки.
- **BR-29.** Папку можно переименовать (например, «Иванов — пресейл» →
  «Иванов — CRM»).
- **BR-30.** Папку можно удалить. Вместе с ней удаляются все её записи:
  транскрипты и аудиофайлы. Удаление требует подтверждения, в котором
  указано, сколько записей будет удалено, и необратимо.
- **BR-31.** В списке записей можно выбрать, что показывать: все записи,
  «Без папки» или конкретную папку.

### Пользователи

- **BR-17.** В системе несколько пользователей. Регистрации нет:
  пользователей создаёт администратор вручную, напрямую в базе данных
  (Prisma Studio). Админки внутри приложения нет.
- **BR-23.** Вход по логину и паролю.
- **BR-22.** Каждый пользователь видит только свои записи.

## Нефункциональные требования

- **NFR-01.** Интерфейс удобен на телефоне так же, как на компьютере.
- **NFR-02.** Транскрибацию выполняет внешний провайдер
  ([ADR 0001](decisions/0001-external-stt-provider.md)). Смена провайдера
  не должна затрагивать ничего, кроме адаптера.
- **NFR-03.** Аудио хранится на сервере приложения, без внешних хранилищ.
- **NFR-04.** Без входа в систему доступа нет ни к одной странице, кроме
  страницы входа.
- **NFR-05.** В интерфейсе три экрана: вход, список записей, транскрипт
  записи. Ориентиры: список — Apple Voice Memos, транскрипт — MacWhisper
  (спикер и время слева, текст справа, без пузырей).

## Планируется после MVP

Эти требования в MVP не реализуются. Они записаны, чтобы не закрывать им
дорогу решениями в MVP. Сроков нет.

- **BR-32.** Пользователь может переименовать спикера в записи
  («Спикер 2» → «Андрей»). Отменяет запрет из BR-11.
- **BR-33.** Голосовые профили. Когда пользователь назвал спикера, система
  запоминает его голос. В следующих записях этого пользователя она узнаёт
  человека и подставляет имя сама. Если не уверена, предлагает имя на
  подтверждение. Незнакомые голоса остаются «Спикер N». Требует BR-32.
- **BR-34.** Профили принадлежат пользователю: другие пользователи их не
  видят и не используют. Пользователь может удалить профиль.

Проработка и риски, включая биометрию (152-ФЗ) и конфликт с
[ADR 0001](decisions/0001-external-stt-provider.md):
[исследование](research/2026-09-voice-profiles.md).

## Вне рамок

- Выбор языка, числа спикеров, словарь терминов.
- Плеер и навигация по аудио из текста.
- Экспорт транскрипта: скачивание файлом, кнопка «скопировать».
- LLM-обработка: саммари, action items, чат по записи.
- Публичные ссылки на транскрипт.
- MCP-сервер и интеграции с внешними инструментами.
- Запись встреч в реальном времени.
- Самостоятельная регистрация пользователей.
- Админка в приложении и роль администратора.
- Смена и восстановление пароля пользователем.
- Переименование спикеров и голосовые профили: запланированы после MVP,
  см. раздел выше.
- Уведомления о готовности: достаточно статуса в списке.
- Ручное исправление текста транскрипта.
- Форматы аудио, кроме формата «Диктофона» на iPhone.
