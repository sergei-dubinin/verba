# План реализации

- **Обновлено:** 2026-09-23
- **Статус:** вертикальный срез 1 запланирован, план прошёл ревью;
  реализация не начата

Реализация идёт вертикальными срезами (термин — в [AGENTS.md](../../AGENTS.md)).
Вертикальный срез закрыт, когда все сценарии с тегами его требований
зелёные в `test:spec` и `test:e2e`. Статус требования вычисляется
прогоном, а не этим файлом: здесь — порядок и границы вертикальных срезов.

У каждого вертикального среза свой файл с шагами, решениями и критерием
готовности. Файл пишется до кода и правится, если по ходу меняется план.

Порядок: вход первым, потому что шаг «я вошёл как» стоит в предыстории
почти каждого `.feature`, а вертикальный срез маленький — на нём дёшево
обкатать тестовую обвязку. Дальше — главный путь продукта (загрузил →
дождался → прочитал), потом управление записями и папки.

Список идёт вместе с загрузкой: сценарии загрузки проверяют, что запись
видна в списке. Требование может зеленеть частями: BR-02 («Загрузить» с
любого экрана списка) проверяется в том числе на экране папки, поэтому
закрывается в вертикальном срезе 5, хотя кнопка появится во втором.
Такие переносы отмечаются ниже.

## Перенесено между вертикальными срезами

- **Стаб провайдера STT и синхронная очередь** — по ADR 0003 входят в
  тестовую обвязку первого вертикального среза, перенесены во второй: в
  первом их не на чем проверить. Правка ADR 0003 — в вертикальном срезе 1.
- **NFR-04, пример «транскрипт чужой записи»** — в вертикальном срезе 1
  шаг открывает адрес транскрипта со случайным id (модели записи ещё нет).
  Во втором, когда появится модель записи, шаг переделать на настоящую
  запись другого пользователя.
- **BR-22** («пользователь не видит чужую запись», «в списке только свои
  записи») — в `auth.feature`, но нужны записи, список и экран
  транскрипта: вертикальный срез 3.
- **BR-02** — кнопка «Загрузить» во втором вертикальном срезе, сценарий
  целиком — в пятом.
- **Тёмная тема** — не входит в первую версию (решение пользователя
  2026-09-23): макеты `*-dark.html` не верстаются ни в одном вертикальном
  срезе MVP. Отдельная задача после MVP.
- **`upload.feature:21`** — «reco» вместо «verba» в тексте шага: поправить
  во втором вертикальном срезе.
