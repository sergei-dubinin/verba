# Вёрстка экранов verba

Поведение экрана задаёт сценарий `@e2e` (скилл `verba-implement`), вид —
макет. Зелёный e2e не значит, что экран похож на макет: NFR-01 и NFR-05 —
дизайн-ревью, а не тест. Этот скилл — про вид.

Источники, в таком порядке:

- `docs/design/screens/*.html` — макеты: фиксированные кадры 390 и
  1280 px, инлайновые стили. Спецификация размеров, текстов и состояний.
- `docs/design/tokens.css` — переменные и классы типографики. Подключён
  в `src/app/globals.css`, в CSS-модулях доступен без импорта.
- `docs/design/README.md` — какой файл какому состоянию соответствует.
- План вертикального среза в `docs/plan/` — решения об отступлениях от
  макетов (например, 01-auth, решение 14).

Макеты не править руками: они выгружаются из холста «verba — экраны».
Тёмной темы в первой версии нет: `*-dark.html` не верстать, `data-theme`
не ставить.

## Как верстать

- **CSS-модуль рядом со страницей** (`page.module.css`,
  `login.module.css`), типографика — глобальными классами из
  `tokens.css`: `className={\`t-body ${styles.label}\`}`. Цвет, отступ,
  радиус — только `var(--…)`.
- **Хексы и пиксели из макета не копировать.** Макет говорит, *какой*
  нужен размер; выражение берётся из токенов. Сначала точный токен, потом
  сумма токенов, потом ближайший токен с записью отступления в план.
- **Страница — `min-height: 100dvh`** и фон `--color-canvas-parchment`,
  как у макетов; `body` остаётся `--color-canvas`.
- **Одна вёрстка на обе ширины**, десктоп — через `@media (min-width:
  734px)` (`--bp-tablet-portrait`). Отдельных компонентов под телефон и
  десктоп не делать.

### Где ошибались раньше

- **`min-height` и `border-box`.** В `globals.css` у всего `box-sizing:
  border-box`, поэтому `padding` входит в `min-height`. «Зона касания
  плюс отступ» — это `calc(...)` в `min-height`, а не `min-height` +
  `padding-block` (так кнопка вышла 44 px вместо 52).
- **Колонка подписей.** Сетка с `max-content` даёт ширину по тексту,
  а в макете колонка фиксированная — поля съезжают влево. Ширину колонки
  задавать явно.
- **Разделитель в карточке** начинается с отступом слева и доходит до
  правого края. Отступ справа — у поля, а не у карточки
  (`padding-inline-start` у карточки).
- **`@media` и токены.** В условии `@media` `var()` не работает — сам
  брейкпоинт пишется числом (`734px`) с комментарием. Классы типографики
  внутри `@media` не применить, но **копировать их значения числами
  нельзя** (`AGENTS.md`; замечание ревью PR #3): при смене шкалы
  типографики такие места разъедутся. Если на телефоне и на десктопе
  разный класс — два элемента с разными классами, по ширине виден один
  (`display: none` у второго; в доступное имя он не входит). Пример —
  `PrimaryLabel` в `src/app/_components/upload.tsx`. Для заголовков, где
  шаги e2e сверяют текст (`toHaveText`), дубль текста не годится — там
  решать отдельно и записывать отступлением.
- **Демо-данные и часовой пояс.** Время в демо-данных ставить через
  `fromZoned` из `src/server/time.ts`, а не `Date.setHours`: у машины
  разработчика свой пояс, и 14:05 превращалось в 12:05.
- **Фон по ширинам разный.** В `list.html` область списка серая
  (parchment), в `list-desktop.html` — белая. Сверять фон каждой ширины.
- **`position: fixed` внутри `backdrop-filter`.** Родитель с
  `backdrop-filter` (липкая панель, полоса «Загрузить») становится
  контейнером для `position: fixed` потомков — оверлей съёживается до
  панели. Шторки и диалоги — нативный `<dialog>` с `showModal()`: он в
  верхнем слое, фон — `::backdrop { background: var(--scrim) }`.
- **`role="alert"` у Next.js.** Next добавляет невидимый анонсер
  переходов с `role="alert"`. Сообщение формы в шагах e2e искать внутри
  `main`, иначе строгий режим Playwright найдёт два элемента.

## Формы

- Клиентский компонент с `useActionState`; Server Action в `actions.ts`
  рядом только вызывает сервисы из `src/server/` (правило из `AGENTS.md`).
- **Состояние «идёт»** — `pending` из `useActionState`: кнопка с
  текстом состояния и спиннером (`aria-hidden`), поля `disabled`, подписи
  приглушены `--color-ink-muted-48`.
- **Ошибка** — `<p role="alert">` под группой полей, рамка группы
  `--color-danger`, `aria-invalid` на полях.
- **После ответа React сбрасывает форму.** Значение, которое должно
  остаться в поле, возвращается в состоянии действия и ставится через
  `defaultValue` с `key` по этому значению. Пароль не возвращать.
- Тексты — ровно как в макете и сценарии: шаги e2e ищут по ним
  (`getByLabel('Логин')`, `getByRole('button', { name: 'Войти' })`).

## Сверка с макетом

Если вертикальный срез добавляет или меняет экран, в его плане есть шаг
сверки: таблица «экран и состояние → макет → 390 px → 1280 px». Сверка —
после зелёного e2e, в запущенном приложении (`pnpm dev`, пользователь
заводится `pnpm user:create`).

1. Через Playwright MCP (`browser_run_code_unsafe`) снять каждое
   состояние на 390×844 и 1280×800 в каталог scratchpad, туда же — макеты
   (`file://…/docs/design/screens/*.html`). Состояние «идёт» ловится
   задержкой ответа через `page.route`; таймеры в коде MCP — через
   `page.waitForTimeout`, `setTimeout` там нет.
   Если MCP отвечает «Browser is already in use» (браузер держит другая
   сессия), снимать своим скриптом на Playwright из проекта: `.mjs` в
   scratchpad с `import { chromium } from
   "<корень>/node_modules/@playwright/test/index.mjs"`, запуск `node`.
   Сессия — cookie `verba_session` с токеном из `createSession`
   (`src/server/auth/sessions.ts`), как в e2e-шаге «я вошёл как».
   Выбор файла — `page.waitForEvent("filechooser")`, «идёт» — `page.route`
   с обработчиком, который не отвечает.
2. Склеить макет и снимок рядом (PIL) и смотреть парами: одна картинка
   на состояние дешевле и нагляднее двух.
3. Сравнивать по порядку: тексты → геометрия (ширины колонок, высоты
   строк и кнопок, края разделителей) → отступы → цвета. Кружок «N»
   внизу — индикатор `next dev`, не расхождение.
4. Расхождение исправить или записать отступлением в «Решения» плана.
   Состояние без макета — тоже отступление: что показываем вместо и
   почему.
5. Что пришлось исправлять и почему — в «Итоги вёрстки» плана. Если
   ошибка повторяемая — дописать её сюда, в «Где ошибались раньше»,
   а новое соответствие размеров — в таблицу.
